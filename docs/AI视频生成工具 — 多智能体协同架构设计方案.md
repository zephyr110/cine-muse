# AI视频生成工具 — 多智能体协同架构设计方案

## 一、设计理念与目标

本方案旨在构建一个**从剧本到成片全流程自动化**的AI视频生成工具。核心设计理念围绕三个关键词展开：

1. **一切皆插件**：参考DeepSeek Harness的“Everything is a Plugin”架构思想，将系统的每个功能模块（模型适配、工具执行、会话管理、Agent循环等）均设计为可插拔的独立组件。这使得系统具备高度的灵活性和可进化能力——Agent可以在运行过程中动态生成、替换或卸载自己的组件。

2. **专业化分工**：借鉴UniVA的Plan-Act双智能体架构和GENMAC的多智能体协同模式，为视频制作的每个专业环节配备专职Sub-Agent，通过协作完成复杂任务。

3. **知识增强**：在关键创作环节外挂RAG知识库，突破模型内化能力的局限，确保输出具备专业深度和一致性。

## 三、核心组件详解

### 3.1 Cordis动态插件运行时

这是整个系统的“地基”，确保插件可以安全地动态加载、卸载和替换。

**关键机制：**

- **可撤销副作用**：每个插件对系统状态所做的任何修改（注册事件监听、分配资源、修改配置），都必须同时留下一个对应的“撤销方法”。插件卸载时，系统按逆序执行这些方法，将状态恢复到插件加载之前。

- **响应式协同依赖**：插件之间可以声明依赖关系。当被依赖的插件（如某个LLM Provider）被替换或移除时，所有依赖它的插件会自动感知并重新加载，确保系统始终处于有效状态。

**核心插件包**：Session日志、工具注册表、Agent循环、模型适配器、作用域注册等——所有这些原本是“底层框架”的组件，在Harness中都是可替换的插件。

### 3.2 中央调度与编排层 (Orchestrator Agent)

Orchestrator是整个系统的“大脑”，负责将用户需求转化为可执行的工作流。

**核心职责：**
1. **任务分解**：将用户输入的创意（如“制作一个关于环保的3分钟短片”）分解为具体的子任务序列：剧本撰写→分镜设计→场景生成→视频生成→配音→剪辑合成。
2. **状态管理**：维护全局上下文，确保每个Sub-Agent都能访问到项目级设定（角色设定、风格指南等）。
3. **异常处理**：当某个Sub-Agent执行失败或输出质量不达标时，触发重试、降级或人工介入流程。

Orchestrator可以采用**Plan-Act双智能体架构**：
- **Planner**：负责制定高阶计划，决定下一步该调用哪个Sub-Agent。
- **Actor**：负责执行具体动作，将计划转化为对Sub-Agent的调用。

### 3.3 专业Sub-Agent插件层

每个Sub-Agent都是一个独立的、可插拔的插件，专精于视频制作的某一环节。这里重点介绍几个核心Agent的详细设计：

#### 3.3.1 剧本撰写Agent

- **输入**：用户创意、风格要求（可选）、RAG检索的参考知识
- **工作流**：
  1. 调用RAG检索剧本结构库和优秀范例库，获取结构模板和风格参考
  2. 基于检索结果生成剧本草稿
  3. 由“剧本审查Agent”从叙事节奏、冲突密度、角色弧光等维度进行评估
  4. 若不合格，根据反馈意见迭代修改
- **输出**：结构化的完整剧本（含场景、对白、动作描述）

#### 3.3.2 分镜脚本Agent

- **输入**：剧本、视觉风格指南
- **工作流**：将每个场景分解为具体镜头，标注景别、构图、摄影机运动
- **输出**：详细分镜脚本（含画面描述和构图参考图）

#### 3.3.3 视频生成Agent

- **输入**：分镜描述、角色/场景参考图
- **工作流**：调用第三方视频生成模型（如Seedance、Veo 3.1）的API，将文本描述和参考图转化为视频片段
- **关键设计**：将模型API封装为标准化插件，便于后续替换为其他模型

#### 3.3.4 质量审查Agent

- **职责**：在每个关键环节后进行自动质量检查
- **检查维度**：
  - **技术检查**：画面清晰度、音画同步、帧率稳定性
  - **语义匹配**：生成内容与分镜描述的匹配度
  - **一致性检查**：角色外观、场景色调在前后镜头中是否一致

#### 3.3.5 一致性守护Agent

- **职责**：贯穿全流程的监督者，确保所有产出符合项目设定
- **机制**：维护“角色视觉参考库”和“场景视觉参考库”，在每段视频生成时进行比对校验

### 3.4 外挂RAG知识库层

RAG知识库是提升各Agent输出质量的“外脑”，尤其适用于剧本、视觉设计等需要大量专业知识的环节。

**各知识库说明：**

| 知识库名称 | 内容 | 服务Agent |
|:---|:---|:---|
| 剧本结构库 | 三幕剧结构、节拍表、类型模板 | 剧本撰写Agent |
| 优秀范例库 | 获奖剧本、经典对白片段 | 剧本撰写Agent |
| 视觉风格库 | 流派配色、大师光影参考图 | 风格设计Agent |
| 服化道图鉴 | 历史服饰、职业装束、道具参考 | 服化道设计Agent |
| 角色设定库 | 性格原型、职业档案 | 选角/剧本Agent |
| 场景背景库 | 不同年代/地域场景参考图 | 场景生成Agent |

**RAG工作流示例**（以剧本撰写为例）：
1. 用户输入“写一个赛博朋克风格的警匪故事”
2. 剧本Agent将“赛博朋克”作为查询向量，在视觉风格库中检索配色、光影参考，同时在剧本结构库中检索“警匪类型”的结构模板
3. 基于检索结果，生成既符合类型规范又具备特定视觉风格的剧本

实际已有案例证明，在视频生成流程中集成RAG的知识检索层，可以有效提升生成内容的相关性和专业度。

## 四、调度与纠错机制

### 4.1 工作流编排

借鉴多Agent协同框架的设计经验，本系统支持多种编排拓扑：

- **Pipeline模式**：适用于线性流程（剧本→分镜→视频生成→剪辑），每个Agent按顺序执行
- **Star模式**：由Orchestrator统一调度所有Sub-Agent，适用于并行任务
- **带反馈的迭代循环**：借鉴GENMAC的DESIGN-GENERATION-REDESIGN三阶段模式，在“生成”和“重设计”之间建立迭代循环，持续优化输出质量

### 4.2 质量门禁机制

在每个关键产出环节设置质量门禁：

```
剧本完成 → 剧本审查Agent评估 → 通过 → 进入分镜阶段
                              → 不通过 → 触发修改迭代（最多3次）
                                            → 仍不通过 → 人工介入
```

### 4.3 异常处理策略

- **超时重试**：视频生成API调用超时时，自动重试（最多2次）
- **降级方案**：当某个Sub-Agent（如特效生成）不可用时，系统可跳过该环节并通知用户
- **完整回滚**：利用Cordis的可撤销副作用机制，当某个插件导致系统异常时，可将其完整卸载并恢复之前状态

### 4.4 人工干预点

在以下关键节点设置“人工确认”或“手动编辑”入口：
- 剧本大纲确认
- 角色设计确认
- 关键分镜确认
- 最终成片导出前

## 五、Sub-Agent实现规范

每个Sub-Agent遵循统一的开发规范：

### 5.1 插件定义

```typescript
// 示例：视频生成Agent插件定义
import { Plugin } from '@deepseek-ai/cordis'

export class VideoGeneratorAgent extends Plugin {
  // 声明依赖
  static inject = ['llmProvider', 'toolRegistry']
  
  // 插件配置
  config: {
    model: 'seedance-v2.0'
    apiKey: string
  }
  
  // 核心方法：被Orchestrator调用
  async execute(context: AgentContext): Promise<AgentOutput> {
    // 1. 从context获取输入（分镜描述、参考图）
    // 2. 调用外部视频模型API
    // 3. 返回生成结果
  }
}
```

### 5.2 输入/输出契约

每个Agent的输入和输出必须遵循标准化的数据格式，确保上下游能够正确对接：

- **输入**：统一从`AgentContext`中读取，包含用户指令、前置产出、全局配置
- **输出**：包含`status`（成功/失败/需修改）、`data`（产出内容）、`feedback`（质量自评）

### 5.3 质量自评机制

每个Agent在完成工作后，需对自身产出进行初步质量评价：
- 评分（0-100）
- 关键指标（如剧本的“情节复杂度”、“角色一致性”）
- 置信度说明

## 六、关键技术选型建议

| 组件 | 推荐方案 | 说明 |
|:---|:---|:---|
| 核心框架 | Cordis | DeepSeek Harness使用的动态组件框架，支持可逆副作用 |
| 编排模式 | Plan-Act双Agent架构 | 参考UniVA的设计 |
| 视频生成 | Seedance / Veo 3.1 | 通过API封装为插件，可替换 |
| RAG向量库 | OpenSearch / Pinecone | 支持图像和文本的多模态检索 |
| 多Agent拓扑 | Pipeline + 迭代循环 | 参考GENMAC的DESIGN-GENERATION-REDESIGN模式 |
| 部署环境 | 容器化（Kubernetes/Cloud Run） | 便于弹性伸缩和版本管理 |

## 七、总结与实施建议

本方案的核心优势在于：
1. **高度模块化**：每个环节都是独立插件，便于开发和替换
2. **质量可控**：通过审查Agent和迭代循环，持续优化输出
3. **知识增强**：RAG补足模型知识盲区，提升专业性
4. **架构先进**：借鉴了UniVA、GENMAC、DeepSeek Harness等业界最新研究成果

**实施路线建议**：
1. **MVP阶段**：先实现“剧本Agent + 视频生成Agent + 简单审查Agent”的最小链路，跑通核心流程
2. **扩展阶段**：逐步增加分镜Agent、配音Agent、剪辑Agent等
3. **增强阶段**：挂接完整的RAG知识库，引入一致性守护Agent和迭代优化循环
