# Cine Muse — AI 视频生成工具产品化实施方案（修订版）

> 基于《AI视频生成工具 — 多智能体协同架构设计方案》的产品落地修订。
> 原方案是纯后端引擎架构；本修订将其落地为一个可演示、可演进的前端产品，同时保留后端引擎的接入契约。

---

## 〇、原方案审查意见（高级产品经理视角）

原方案架构完整、借鉴了业界前沿（Cordis 可逆副作用、Plan-Act、GENMAC 迭代循环），但作为**产品方案**存在以下缺口：

| # | 问题 | 修订 |
|:--|:-----|:-----|
| 1 | **无前端产品设计**：Web UI 仅一行带过，用户如何创建项目、观察流程、执行人工确认均未定义 | 新增完整产品层：信息架构、页面规划、交互规范（本文档第二~四章） |
| 2 | **15 个 Sub-Agent 一次性全上**：不符合渐进式交付，MVP 负担过重 | 分级实施：MVP 核心 8 个 Agent，扩展期补齐至 15 个 |
| 3 | **质量门禁是纯后端逻辑**：用户看不到"3 次迭代上限"、"人工介入"何时触发 | 门禁状态上屏：节点卡片实时显示通过/打回/待人工，迭代次数可视化 |
| 4 | **4 个人工干预点未产品化**：剧本大纲、角色设计、关键分镜、导出前确认 | 定义为"确认节点"（Human-in-the-loop）：节点挂起 → 通知 → 审核抽屉 → 批准/打回 |
| 5 | **缺少项目生命周期**：无项目级状态机（草稿/执行中/暂停/完成/失败） | 新增项目状态机，工作台按状态分组展示 |
| 6 | **编排拓扑（Pipeline/Star/迭代）无用户入口** | 新增"工作流模板"概念：完整流水线 / 快速预览 / 自定义 |
| 7 | **RAG 知识库是后端概念** | 产品化为可管理的"知识库"页面：7 个库、条目统计、启用开关 |
| 8 | **缺少 UI 与引擎的通信契约** | 新增引擎抽象层：本期用模拟适配器驱动，接口与真实引擎 1:1 对齐，未来零侵入替换 |
| 9 | 视频生成模型（Seedance/Veo）等外部依赖未定义接入形态 | 新增"模型服务"设置页：模型适配器（LLM/视频/TTS）配置与状态 |

## 一、产品定位与 MVP 范围

**定位**：面向创作者与小型影视团队的"从剧本到成片"一站式 AI 视频生产工作台。

**MVP 范围（本期实施）**：

- ✅ 项目工作台（概览、统计、项目列表、活动流）
- ✅ 新建项目向导（创意 → 风格 → 规格 → 模板）
- ✅ 项目工作区：多智能体工作流画布（实时状态、质量门禁、迭代记录）
- ✅ 人工确认节点（审核抽屉：产出物预览 + 质量评估 + 批准/打回）
- ✅ 知识库管理（RAG 7 库的元数据管理）
- ✅ 智能体目录（Agent 注册表视图 + 启用/模型分配）
- ✅ 模型服务设置（适配器配置）
- ✅ 模拟编排引擎（状态机 + 定时推进 + 种子数据），接口契约与真实引擎一致
- ❌ 暂缓：真实模型 API 调用、账号体系、多人协作、命令面板、成片在线播放器（占位可留）

## 三、工作流引擎设计（模拟适配器 + 真实契约）

### 3.1 引擎抽象层

```
UI 层（页面/组件）
    │  dispatch(action)
    ▼
Store（useReducer + Context + localStorage 持久化）
    │
    ▼
Engine Reducer（纯函数状态机：执行 action → 返回新 state + side effects 队列）
    │
    ├── MockAdapter（本期）：定时 tick 推进节点执行，模拟耗时/成功率/质量分
    └── HttpAdapter（未来）：将 action 序列化为 API 调用，映射真实引擎事件
```

- 引擎与 UI 通过 **action 契约**通信：`START_PROJECT / APPROVE_STAGE / REJECT_STAGE / SKIP_STAGE / TICK / CREATE_PROJECT ...`
- 引擎向 UI 的回报通过 state 中的 **event log** 驱动活动流与通知。

### 3.2 节点状态机

```
PENDING → RUNNING → (产出 + 自评) → REVIEW(门禁) ──通过──▶ COMPLETED
                                   └─不通过─▶ ITERATING(重跑) → RUNNING（迭代计数 +1，上限 3 次）
COMPLETED 若为确认节点 → WAITING_APPROVAL → APPROVED / REJECTED(打回重跑)
FAILED（异常/超限）→ 可手动 RETRY 或 SKIP（降级跳过并通知）
```

### 3.3 项目状态机

```
DRAFT → QUEUED → EXECUTING → COMPLETED / FAILED
             ↕（任何确认节点挂起时 → WAITING_APPROVAL 对外表现，内部仍 EXECUTING）
```

### 3.4 MVP 工作流模板（Pipeline 顺序）

1. **剧本撰写**（剧本 Agent）→ 门禁：剧本审查 Agent
2. **分镜脚本**（分镜 Agent）→ 门禁：一致性守护 Agent
3. **风格设计**（风格 Agent）→ 确认节点：角色/风格设定（人工）
4. **场景生成**（场景 Agent）
5. **视频生成**（视频 Agent）→ 门禁：视觉质检 Agent
6. **配音合成**（配音 Agent）
7. **剪辑合成**（剪辑 Agent）→ 确认节点：成片导出前（人工）

> 模板 = 上述 7 个执行节点 + 2 个确认节点 + 门禁；"快速预览"模板 = 剧本 → 视频生成 → 成片（3 节点）。

### 3.5 质量评估契约（沿用原方案 5.3）

每个节点输出：`score (0-100)`、`metrics[]`（关键指标键值）、`confidence`、`feedback`（自评意见）。
门禁通过线：`score >= 75`；连续 3 次低于 → 节点 FAILED → 人工介入。

### 3.6 资产库与干预深度谱系（产品补充）

**资产库（Asset Library）**：用户自行维护的角色/场景/道具/风格素材卡，全局唯一、跨项目复用。
项目通过**绑定**（AssetBinding，含"在本项目中的用途"）引用资产；agents 在对应环节**消费**绑定资产作为生成约束——
这正是原方案 3.3.5 一致性守护 Agent"角色/场景视觉参考库"的**显式化**：把隐式参考变成用户可管理的资产。

| 消费环节 | 消费资产 | 效果 |
|:---|:---|:---|
| 剧本撰写 | 道具/角色卡 | 叙事动机锚点（评分 +3） |
| 风格设定 | 角色/风格卡 | 外观设定受约束，辨识度提升（+4） |
| 场景生成 | 场景/风格卡 | 环境还原度提升（+4） |
| 视频生成 | 角色/场景/道具卡 | 跨镜头一致性比对锚点（+3） |
| 配音合成 | 角色卡 | 声线设定提升情绪传达（+3） |

**干预深度谱系**（回答"是否需要新增可干预每个环节的模式"——不必打断，绑定即干预）：

| 档位 | 模式 | 流程 | 典型用途 |
|:---|:---|:---|:---|
| L0 | 全自动（auto） | 零打断，checkpoint 自动通过 | 批量出片 / 复跑 |
| L1 | 引导式（guided，默认） | 不打断，agents 消费绑定资产 | "指定这张脸"式前置干预，覆盖 80% 需求 |
| L2 | 审查式（review） | 关键节点暂停人工确认 | 需要把守质量的创作流程 |
| L3 | 手作式（manual） | 审查式 + 每环节产出可手动改写 | 人机协作精修 |

关键设计：**干预不必表现为打断**——L1 的资产绑定是"前置干预"，流程全程不中断；
L2/L3 的确认点可配置；模式**可随时切换**，切换为 L0/L1 时挂起的确认节点自动批准并继续。
另外：被项目引用的资产**禁止硬删**（引用保护）；新建项目时按题材/风格标签**自动推荐**可绑定资产。

## 四、交互设计规范（高级 UI/UX 视角）

1. **状态可视化**：节点卡片用颜色 + 图标双重编码（Pending=灰、Running=蓝+pulse、Approved/Completed=绿、Rejected=红、WAITING_APPROVAL=琥珀+提示徽标）；运行中节点显示进度动画；所有状态变化伴随 sonner toast。
2. **确认节点交互**：挂起时侧边栏徽标计数 + toast 提醒；审核抽屉内展示完整产出物与质量评估；打回必须填写原因（校验非空），原因进入迭代记录。
3. **详情抽屉**：点击任意节点打开；Tabs 组织：产出物（内容预览）/ 质量评估（环形分数 + 指标条）/ 审查反馈 / 迭代记录（时间线）。
4. **新建向导**：4 步线性引导，每步实时摘要；风格预设用视觉卡片单选；规格含时长/比例/画质下拉。
5. **空状态与骨架**：列表/画布加载使用 skeleton；无项目时展示引导创建。
6. **反馈及时性**：所有异步推进（tick）通过通知层收口，避免 UI 无感变化。
7. **暗色模式**：next-themes 已集成，全组件走 CSS 变量，随系统切换。
